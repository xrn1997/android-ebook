# 长目录的浏览与选择形态：目录倒序会话内有效、下载面板按百章分组

阅读器有两个长目录入口——章节目录抽屉与离线下载面板。目录加一个仅本次会话有效的倒序开关；下载面板的单层平铺改为每 100 章一组的可展开分组，组头可整组勾选，并为单次下发量加 500 章软上限（只提醒、不阻止）。这次形态调整同时定下三条容易被后来者改回去的口径：倒序不落盘、"有缓存文件"不等于"内容正确"因而不作任何判据、目录的快速滚动条不因有了倒序而降级。

## 动机

目录抽屉只有正序，连载书的读者要翻到最新章只能靠右侧快速滚动条从顶拖到底；下载面板则把全部章节平铺进一个半屏高的列表，三千章的书要在半屏里手滚找章。后者在实现时曾被明确记过一笔"大目录快速滚动可加，本面板以选择为目的、不引入"，这次把该缺口闭合。

## 决策

1. **目录倒序仅在本次会话内有效、不落盘**。这个开关的默认值本身就有争议：连载书读者要倒序、已完结书读者要正序，而"上次开了倒序、这次找不到最新章节"的困惑比"每次都要重切一次"更贵。状态因此声明在抽屉函数顶层而非其进出场动画之内——关抽屉不丢、退出阅读器自然回正序。

2. **下载面板按 100 章分组，组头承担整组勾选**。下载面板的用途是"按范围取章"（下最近三百章、补全后半本），分组的导航面是组数而非章数，比给它单独加一个倒序开关更贴合用途；组头勾选让"下最近三百章"从三十次点击降到三四次。组头勾选一律选中整组 100 章（含已缓存章，仍按既有的强制刷新语义重下），组头显示的三态与已缓存计数只作反馈。

3. **单次下发 500 章为软上限：超过只多一次确认，不阻止**。长书整本离线是正当操作，硬截断会让它变得做不成；而组头勾选让"一次选中上百章"只需一次点击，没有护栏时长书误触会一口气入库数千条任务、占住前台的离线下载服务数小时。确认弹窗必须携带决策信息——写明将一次性下发 N 个下载任务、耗时较长、期间持续占用离线下载服务；**刻意不自称"上限"**（它能被越过，用一条自己马上会推翻的规则做警示会削弱后续所有警示的可信度），也**不写任何具体时长或配额数字**（那由系统策略决定，写死会在策略变化时变成假话）。确认键用动作动词「继续下载」。

4. **"是否已缓存"不作任何决策判据**。缓存文件存在不等于内容正确——缓存失败时也会有文件落盘，据此判定"已缓存"会得出错误结论。因此已缓存徽章与组头计数只作展示：既不参与勾选状态，也不参与上限判定。

5. **目录的快速滚动条不作降级**。上千章的目录靠纯滑动翻找效率低，即使有了倒序，滚动条仍是"跳到书中任意位置"的唯一手段。

## 权衡

- **给下载面板加倒序（被拒）**：两个长目录用两套导航手法，用户要分别学；且倒序只解决"找最新"，不解决"在三千章里定位到某一章"。分组同时改善这两件事。
- **硬上限 500 章（被拒）**：会让"全选"与整本离线在长书上直接不可用，等于用一个护栏砍掉一个正当能力。
- **倒序落盘（被拒）**：见决策 1，默认值有争议时，不记忆比记错更便宜。
- **保留"仅未缓存"快捷选择**：它是唯一由用户触发的、以缓存存在性为输入的选择入口（打开面板时的默认预勾选同样按未缓存过滤，那是既有行为、不在本次改动范围内），与决策 4 有张力。保留的理由是"补全还没下载的部分"仍是真实需求，且点击意图明确、结果在组头三态上立即可见；代价是那些"文件在但内容错"的章不会被它修到，要修得手动展开或全选。若该张力日后被判定不可接受，去掉它是纯删除。

## 下游影响

- 新增 `module_book` 的 `reader/ChapterSelection.kt`（分组切分、组头三态、整组勾选、倒序索引换算、组头行号、上限判定等全部可测语义）与 `reader/ChapterDownloadSheet.kt`（下载面板从 `ReaderPanels.kt` 搬出后改造）。
- 目录抽屉新增会话内倒序状态；章号、当前章高亮、点击跳转一律改取"原始章序号"，倒序后首行仍显示绝对章号。
- 下载面板新增 `focusIndex` 入参：打开时默认只展开含当前章的那一组，并把该组头滚到列表顶部。
- 组头用 `stickyHeader` 吸附，且是**满宽直角的实心底色**——圆角的四个角会让下方滚过的章行文字透出来。
- 已缓存徽章与新增的组头计数降级为纯信息，不再参与任何决策。
- 新增文案：目录顺序两态与切换描述、组范围、组缓存计数、组展开/收起描述、超量批量确认的正文与确认键。
