# 按书暂停与下载中心操作面板

离线下载支持**按书暂停**：某本书的排队任务保留、服务跳过该书取篇，可随时继续。同时把下载中心二级选章页的操作面收敛为「右下主 FAB + 勾选工具面板 + 书头动作列」：面板只留四个选择工具，书级动作（下载 / 暂停 / 继续）收成书头一枚三态钮、上排一枚「取消本书」。这次定下四条容易被后来者改回去的口径：暂停是持久化的书级事实、「下载」与「继续下载」是同一按钮的两种语境、取不到下一章不等于队列跑空、确认下载即解除该书暂停。

## 动机

下载中心二级页此前只有「下载 X 章」与「取消本书」（取消藏在页头、下载在底部，风格割裂），缺一个「暂停」——书下到一半想停下但不丢任务，只能取消重来。批量选章也不便：全选动辄数千章、仅未缓存也可能几百章，用户需要「第 X 章到第 Y 章」的范围选择。操作面本身经多轮设计迭代（固定底栏三键 → 七项全收进一个展开式 FAB → 分组面板 → 书级动作挪出面板）收敛为一个判据：**四个选择工具是「选哪些」的前一步、书级动作是「这本书怎么办」，两者不共用一条横排**。

## 决策

1. **按书暂停 = 持久化的书级事实，落在独立表 `paused_book`（主键 note_url）**。不放 `download_chapter` 的行级列（书级状态落在任务行上，加任务时会产生「一部分行暂停、一部分行不暂停」的混合态）；不落内存（进程重启后暂停静默失效，等于用户没暂停过）。暂停书的新任务自动继承暂停语义（表是按书生效的），确认下载时显式解除。
2. **跳过暂停书是队列策略，在仓库层做**：取下一章的遍历循环里查一次暂停集跳过，`DownloadChapterDao` 的既有查询与测试假件零改动。服务的全局暂停（通知按钮）语义不变，两者正交：全局暂停停整个消费循环，按书暂停只影响取篇时的候选集。
3. **「下载」「继续下载」「暂停」合并为同一枚三态主操作**：「下载」与「继续下载」本就是「让这本书下起来」的同一个意图——有有效勾选＝入队下发（书已暂停则顺带解除）；已暂停且无勾选＝继续跑既有队列。「取消本书」独立一枚，从队列清空该书任务并清掉暂停标记。（2026-09-12 修订：**「暂停本书」不再是并排的另一枚，而是由同一枚承载**——三态由纯函数按「有没有任务 / 有没有暂停 / 有没有可下发的勾选」判定，挪到书头右侧；理由与被拒的排法见修订说明。）
4. **取不到下一章 ≠ 队列跑空**：服务取篇为空时分流——先清理孤儿行（书已不在架的任务），若表内仍有任务则全部处于暂停书，转入暂停态并**静默停服**（不发「下载完成」误报——暂停书的任务没下完；也省 dataSync 前台配额，继续时 RESUME Intent 经 getForegroundService 随时拉起）。
5. **操作面 = 右下主 FAB + 勾选工具面板 + 书头动作列**：面板只放「勾选」四工具（全选/仅未缓存/范围/清除，图标圆钮+下标签），**一排固定、不随队列状态增减**；书级动作在书头状态胶囊右侧上下两枚——上「取消本书」（描边）、下三态主操作（主色实底）。（2026-09-12 修订：原「本书」组与主操作实底圆钮置尾的排法作废——同一条横排里按钮个数随状态变化，点击位会跳动且会被破坏性动作继承；原「无排队任务且无有效勾选时整组消失」的显隐规则改为一律常驻、按状态**置灰**。选中数仍不放 FAB 角标，与书头状态胶囊（共 N 章 · 已选 M 章 · 下载中|排队中|已暂停）共用一行、随勾选实时刷新。）
6. **范围选择填入勾选而非直接下发**：起/止章号对话框（1-based、校验空/越界/起>止）确定后替换当前勾选并滚动到范围起点，用户能在列表里看到将下什么、可再微调，再走主操作；超过 500 章仍触发既有的软上限二次确认。对话框**带默认区间**，不让用户对着两个空框从零输入：已有勾选取勾选边界（范围工具就是把这段改成精确范围），无勾选取「当前章起 50 章」——与阅读器入口的预勾选同一个窗口（同一函数，免得两处各写一个 50 在边界上分叉），一级入口没有当前章时退化为第 1 章起 50 章。
7. **暂停不打断已发出的当前章请求**：服务按章推进，暂停在下一轮取篇时生效——当前章抓完即停，不存在半章状态。

## 权衡

- **暂停放任务行级列（被拒）**：混合态问题见决策 1，且取消本书/清空队列时要连带清列，表是流水语义、不该背书级状态。
- **「下载」与「继续」分设两按钮（被拒）**：同一意图两个入口，用户要在两个长得差不多的按钮间判断「我现在该按哪个」。
- **书级动作留在面板内、只把两端钉死（被挪位置）**：等比预览里量过这一版——「取消本书」钉左（48dp）、三态主操作钉右（263dp），三帧坐标一字不差，点击位漂移已解决。仍被挪出面板：面板要同时装下四个选择工具与两枚书级动作，纵向挤在两排之间，而书头右侧本就是一块与封面等高的空白；且「这本书怎么办」在列表里换一本书就得重新展开面板，书头跟着页头常驻。
- **三态里让「下载」常驻、暂停只留通知栏入口（被拒）**：省掉「暂停压过下载」那一次额外点击，代价是队列正在跑时这一页没有刹车——用户在这页新勾了一批想停下重来，得先下拉通知栏，比两击更远。
- **全暂停时保持前台服务存活显示「已暂停」（被拒）**：空闲前台服务白烧 dataSync 24h/6h 配额；任务在库里，继续入口（下载管理页/通知 RESUME）都能拉起服务。
- **范围选择直接下发（被拒）**：少一次点击，但看不到「已跳过 N 章（已在队列）」等统计、不能微调个别章；填入勾选把最终决定权留给用户确认那一下。
- **面板常驻底栏（被拒）**：占一到两行固定高度，列表被压；收进 FAB 平时零占位，代价是每次操作多一击（含下载），经用户确认接受。

## 下游影响

- `lib_ebook_db` v8：新表 `paused_book`（实体 + DAO + `MIGRATION_7_8`），schema 链与契约测试同步升版。
- `DownloadRepository`：取篇/判队尾跳过暂停书；新增按书暂停/继续/查暂停集；取消本书与清空队列连带清暂停行；新增孤儿行清理（承接原「队列表空时 clearAll」的清理职责）。
- `DownloadService`：取篇为空的分支改为「清孤儿 → 仍有任务＝全在暂停书 → 发 Paused 并静默停服」，全局暂停路径的空分支按表内计数分流 Paused/Finished。
- `DownloadManageViewModel`：分组数据与二级装载合入暂停态；确认下载先解除该书暂停；继续下载走 RESUME Intent。
- `module_book` 二级页整屏重排（书头状态胶囊 + 预演小字 + 右侧动作列 + 主 FAB 勾选工具面板 + 范围对话框）；一级书行加「已暂停」胶囊，一级维持只展示+导航。
- 新增范围解析纯逻辑（1-based 起止 → 0-based 索引闭区间，非法输入返回 null）与书级主操作三态判定/置灰规则进 `ChapterSelection.kt`，JVM 单测锁定。

## 修订说明（2026-09-12）

- 二级操作面形态经用户多轮评审收敛：固定底栏三键（暂停/取消 outlined + 下载 filled）→ 七项全收进一个竖排展开式 FAB（过密）→ **分组面板**（勾选/本书两组、图标圆钮+下标签统一语言、左右排布）。选中数从「下载 X 章」按钮文案与 FAB 角标方案撤回，并入书头状态胶囊。
- **面板的状态矩阵与图标口径（同日追加）**。「本书」组的显隐与内容按 5 种状态定死，其中两格是设计评审时补的：无排队任务且有有效勾选 → 只剩主操作「下载」（按下去就是第一次下发）；有任务未暂停 → 「暂停本书 / 取消本书 / 下载」（零有效勾选时「下载」置灰）；有任务已暂停且零有效勾选 → 「取消本书 / 继续下载」；已暂停但有新勾选 → 主操作回到「下载」（入库顺带解除暂停，故不与「继续下载」并列）；无任务且无勾选 → 整组消失。**同一面板内两组各有一对图标同形必须拆开**：「仅未缓存」与主操作「下载」都画下载箭头（把「选哪些」说成「开始下」）、「清除」与「取消本书」都画垃圾桶（把「清空勾选」说成「取消整本下载」，两者代价不对等），故按语义各换一枚（「仅未缓存」画云端未落地的斜杠云、「清除」画取消选择）。勾选组中间两枚同日又各换一次形，因为用户读到的是「含义不明」：漏斗在本页别处是排序/筛选的意思、滑块刻度像「调节一个值」的条，而这两枚给出的都是**一批勾选**，于是改成斜杠云（云端那份还没落到本地）与 123（它打开的是起止章号输入框）。展开时**不设遮罩**：列表仍可点选，「已选 M 章」胶囊与行内状态随操作实时刷新（面板只压住列表下缘，上方列表可见可点）；「暂停本书」与四个筛选工具执行后保持展开（接着调）。**「下载」「继续下载」执行后收起面板这条已被同日的新决策撤销，见下文「面板改为常驻」**。
- **面板底部小字改为预演语义**：按当前勾选先说「将跳过 N 章（已在下载队列）」；若勾中的章全在队列则改说「已选章节均在下载队列」。原「已跳过」是按下确认后的过去时，常驻面板里读起来像已经发生。
- **一级书行补「已暂停」胶囊（同日追加）**：暂停是书级事实，不标出来时一级只剩「剩余 N 章」却一直不推进，用户无从判断是卡住还是被自己暂停了；胶囊只展示、不可点——一级维持「只展示 + 导航」，切换暂停仍只在二级面板与下载通知上做。
- **选中态与面板分层重做（同日追加）**：章节行的选中态原为整行 `surfaceContainerHigh` 圆角色块，与悬浮面板**同一色值**——面板浮在同色选中块上只靠投影区分，用户读到的是「控制界面不明显」；色块本身在千章全选时并成一片实心灰。改为：行 = 左缘 3dp `primary` 指示条 + `primary` 8% 薄纱 + 勾中章名转主色；面板 = `surfaceContainerHighest` + 1dp `outlineVariant` 描边 + 16dp 投影。两层从此按**色相**分（主色 vs 中性最高档），不再按投影强弱分。两条硬约束：**指示条走 `drawBehind` 且必须排在 `clip` 之前**（`clip` 只裁剪排在它后面的修饰符与子内容，放后面会被行尾圆角啃掉端头，上下相邻的勾中行并不成一条带）；**薄纱只圆右半边**（左缘与指示条齐平、上下不留缝，连续行才会并成一整块高亮带，而非每行一枚小药片）。面板工具钮同时改成「无底 → 实底」的梯度：`Default`/`Danger` 不铺底（原 `Default` 铺 `surfaceVariant` 圆点，比面板底色还深，四枚一排等于一圈泥点），主操作独占全面板唯一的 `primary` 实底；「取消本书」只染 `error` 不给色块——它自带二次确认，不必预先吓人。曾一度给进阶工具「范围」单插一档 `Tonal` 浅底（`primaryContainer`）凑成三档，同日撤销：一组四枚里唯一带底的那枚读起来像「已经激活的开关」，而不是一个动作——它是筛选工具，不承载当前筛选条件的状态。
- **本轮被拒的两个选中态方案**：**整行 `secondaryContainer`**（与阅读器目录「当前章」同款语言，跨页一致性最好）——千章全选时整屏是实心色，且面板必须再往深色或反色档拉开才压得住，代价大于收益；**行底完全留白、只靠勾选框与文字色**（列表最干净、绝无撞色可能）——单章零散勾选时边界只剩文字色可辨，扫读不如指示条带子直观。
- **面板改为常驻、不再自动收起（同日追加，撤销「下发后收起」）**：收起写在超限预检**之前**，于是出现怪现象——那一刻还没执行任何东西、只弹出一个模态确认框，面板却已在框后面收掉，用户点「取消」想微调再下就得重新展开一次；再者下发是连批操作（下一批、看进度、再挑一批），每次收起都要重新展开控制台。改后主操作执行后保持展开，**收起只由 FAB 上的 X 承担**；下发结果不再靠"面板消失"表达，交给行内新打的「排队中」标签、置灰的主操作与面板底部那句预演（同日再修订：预演小字已随书级动作搬进书头）。代价是面板长期占住右下角，于是两处让位改成按面板**实测**高度（`onSizeChanged`）动态叠加：列表末端 `contentPadding` 加面板全高（否则书末的章永久压在面板底下）、滚动条轨道在展开期间截短（面板不透明，轨道下段整截在它后面，滑块拖进去就看不见）。面板高度当时受「本书」组显隐与底部预演小字影响，不可写死估算值——那会在改文案时悄悄失效（同日修订：「本书」组与那句预演小字都已离开面板，实测保留仍成立，但理由换成字号缩放与标签换行）。原「面板是瞬时的，不为它截短轨道」这条前提随之作废。
- **书级动作收成书头一枚三态钮（同日追加，改写决策 3 与决策 5 的操作面部分）**：触发点是「暂停、继续下载、下载这三个能合并么，一个按钮就够切换下载状态」。真正的病灶不是按钮多，而是**点击位不稳**：在等比预览里量过「本书」组（面板内容宽 286dp、`Arrangement.SpaceEvenly` 按个数重新分配间隔），主操作落在 155 / 215 / 244 三处（1 枚 / 2 枚 / 3 枚），两两差 89dp 与 29dp；更糟的是三枚那帧「取消本书」正落在单枚那帧「下载」的坐标 155 上——面板随队列状态增减按钮，用户按肌肉记忆点下去，**同一坐标上一帧是下发、这一帧是清空整本任务的取消**。方案取「胶囊 + 钉两端」的思路并挪位置：两枚书级动作搬出悬浮面板、进书头状态胶囊右侧的空白列，上下各一枚、位置与个数从此无关（列宽 76dp、两枚 30dp + 4dp 间距 = 64dp，恰与封面等高）。
  - **三态判定是纯函数**（`bookDownloadActionOf`：有任务未暂停 → 暂停；已暂停且零有效勾选 → 继续；其余 → 下载；JVM 单测锁住 5 格矩阵）。**「暂停」压过「下载」**是一枚按钮必须替用户挑一件事时的取舍：队列在跑又新勾了几章那一格先给「停住正在发生的」，否则跑着的队列在这页没有刹车，只能绕到通知栏去停；想下那批新勾选只需再点一次——暂停后有效勾选数不变，同一枚钮当场变回「下载」，而入库路径本就解除暂停（`confirmDownload` 先 `resumeBook` 再 `startDownload`）。判据取「有没有任务」而非「当前有没有章在传」：任务已入库而服务未轮到那一格按传输中判断会漏掉暂停入口。
  - **置灰只跟「下载」绑定**（`isEnabledWith`）：一个都没勾时按下去没有对象，置灰；暂停/继续面对的是既有队列，与本次勾选无关，置灰等于锁死刹车。**取代了原先「无排队任务且无有效勾选时整组消失」的显隐规则**——位置固定本身就是这一轮的目的，没资格按状态从屏幕上消失。
  - **不用 Material `Button`**：它强制约 40dp 最小可点高，两枚摞不进 64dp 的封面通栏，故手搓 `Box` + `clip`/`background`/`border`/`clickable(role = Button)`；`clip` 排在 `background`、`border`、`clickable` 之前以裁住水波纹。上行「取消本书」为描边 `error`（保留二次确认，不预先吓人），下行三态钮为 `primary` 实底、禁用时落 `onSurface` 12%/38% 两档。
  - **顺带补一格状态胶囊**：任务已入库但服务未开始时 `activeChapterIndex` 为 null，原先书头什么都不画，读起来像"什么都没发生"，现补「排队中」。**面板底部那句预演小字随之搬进书头胶囊行下方**（它说的是"按下去会发生什么"，跟的是那枚按钮）。面板从此是**固定四工具一排**（全选/仅未缓存/范围/清除），不再随队列状态增减——「本书」组与 `PanelToolStyle` 分档（面板内只剩无底一档）一并删除，`download_manage_group_book` 文案移除，零新增字符串。代价：位置不再随状态跳动，但两枚钮常驻占掉书头 76dp 宽，长书名可用宽度变窄（待装机在不同字号与窄屏下核对）。
