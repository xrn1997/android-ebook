# 重复书目的处置收拢到导入时点，判重口径为 comment_key 主键相等

决定三件互相牵连的事：**重复检测从书架加载后的被动扫描改为导入时点拦截**——待导入文件的标题+作者算出 `comment_key`，与书架每本书的当前主键比对，命中即弹处置框，书架侧的被动扫描整条链删除；**判重只认 `comment_key` 主键相等，不做模糊打分**；`ImportBookActivity` 顶栏回到基类 Toolbar，`CAppTransparentTheme` 下线。

## 背景

书架侧的提示是"事后 nag"：书目已经在书架上了，才在进书架时弹一条 SnackBar 问要不要合并。两个问题同时暴露：

- **入口重复且更差**：重复是在导入那一刻被创造的；同一个判断在导入时点做，用户手里正拿着那个文件、处置意图明确；在书架时点做，用户得先回想"这两本是不是同一本"。两条链并存后，书架侧那条被删了调用方，留下 `BookListViewModel` 三个零调用方的成员与一份仍声称"由 BookShelfPage 调用"的 KDoc。
- **模糊打分在导入时点没有输入**：`BookMergeScorer` 的强信号是章名序列相似度与段落指纹，两者都要求先把书切完章。导入前判重必须发生在切章之前——切一遍 2000 章的文件只为判断"是不是同名书"，代价与收益不成比例。剩下的书名+作者两个中信号，恰恰就是 `comment_key` 的两个输入项：既然精确键已经算了，模糊打分是在用概率方法重做一件已有确定解的事。

## 决策

1. **判重只认主键**：`DuplicateBookDetector.findMatchesFor` 比的是 `book_group` 里 `is_primary = 1` 那一行的 `comment_key`，**不是** `book_info.name`。键含作者（`CommentKey.compute` 归一化书名+作者），只比书名会把"同名不同作者"判成同一本书，误判即给出会删条目的处置——误判一次的代价是删掉另一本无辜的书，保守方向：**宁可漏提示，不可误并**。同时主键正是修键面板维护的那一行，比主键意味着用户改过匹配名之后检测自动跟随；比显示书名则两边脱节。作者解析两边不一致时算出不同键 → 不判重，这是刻意的漏报。
2. **处置动作四个，非破坏的那个占主按钮位**：继续添加（两条目共存，同键则评论读并集天然共享，无破坏性）、智能合并（新条目多出的**尾部章节**补进旧条目，旧条目 `noteUrl`/进度/键全保留，新条目退场，低破坏）、覆盖（新条目替换全部，删旧之前先 `absorbGroupKeys` 吸收关联键，高破坏）、跳过（不导入本文件）。"继续添加"是跨来源共存这套模型的主场景——同一作品多来源并存的唯一表达方式。顺序一律**先导入、后处置**，反过来一旦导入抛异常旧条目已毁新条目没进来用户两头空。覆盖必须先 `absorbGroupKeys`：旧条目身上可能挂着历次合并攒下的 secondary 键，不先吸收就连读并集一起丢。`mergeTailChapters` 只补尾不插中间，判据是旧书归一化章名序列是新书的**前缀**——前缀分叉说明两本切分规则不一致，按位置补章会把正文错位插进旧书，此时整笔放弃（返回 `Diverged`，两本共存）。补章目标必须是本地书（网络书的正文在书源那边无载体可补），索引取现有最大 `durChapterIndex + 1` 不用 `size`（历史删章留下的洞会让 `size` 与末位索引不等，从而覆写既有章文件与同 `content_ref` 的行）。暂停门用 `AtomicReference`，`getAndSet(null)` 了结：门由 IO 线程置入主线程取出，普通 `var` 无跨线程可见性保证；一次性取出同时让连点天然幂等。
3. **顶栏回到基类，`CAppTransparentTheme` 下线**：导入页、详情页、搜索页原先挂透明主题配合整页水平滑入滑出，透明主题与 Compose 基类的 Toolbar/insets 装配叠在一起后页面自行接管顶栏的成本高于收益。导入页改由基类 Toolbar 出标题与返回箭头，整页滑入滑出动画删除；详情页不再自绘 `Scaffold + TopAppBar`——为一颗「编辑匹配信息」按钮自绘整条顶栏，要连带接管返回箭头、状态栏 insets、容器配色（基类 `ToolbarLayout` 没有 actions 插槽），漏一项就是静默缺陷，实测已漏过一次返回箭头；修键入口落到详情页正文底部的 `TextButton`。资源侧 `lib_book_common/res/values/styles.xml`（`CAppTransparentTheme` 唯一定义处）随引用清零一并删除。manifest 双份替换关系（集成清单与独立清单逐条一致、同步增删）在主题改动上同样需两份同步。

## 权衡

- **放弃模糊匹配**：同名不同作者、或作者解析结果两边不一致的两本同一书不再被提示。替代路径是修键面板人工归一，以及处置后同键条目天然共享评论。被删的五信号算法与测试若要找回，得先解决"导入时点没有章名"这个输入侧障碍。
- **同键共存不再是异常状态**：书架上同一作品出现多个条目是允许的（读并集共享评论），所以判重的目的从"消灭重复"降级为"告知并给出处置"，这也是非破坏动作占主按钮位的理由。
- **转场体验有损失**：导入页失去水平滑入滑出，与 Compose 迁移终态里"行为一比一移植"的表述在该页不再成立（阅读器、书评页仍成立）。
- **已知遗留**：覆盖与合并都会删条目，而 `BookRepository.removeFromShelf` 不清 `download_chapter`——这是「详情页 → 从书架移除」一直就有的行为，本轮没有把删除路径改窄，只是多了一个触发口。后果有界：那本书的章抓取必然失败，失败章在重试耗尽后会被移出下载队列（`DownloadService.downloading` 的既有出队规则），不会永久滞留。要根治应在 `removeFromShelf` 的调用侧统一收口（`download_chapter` 在 `lib_ebook_db`，仓库层归属不同，不宜由共享层反向依赖功能模块的下载仓库），单独一次改动处理。

## 落地状态

- `DuplicateBookDetectorTest` 锁判重口径：同书同作者命中、同名不同作者不命中、作者占位词两边归空、比对主键而非显示名（改过匹配名后检测跟随）、secondary 键不参与判重、多命中全部返回并按来源标注 `isLocal`。
- `BookRepositoryTest` 锁处置原语：`absorbGroupKeys` 吸收含 secondary 且不重复加同名键、`mergeTailChapters` 前缀对齐只补尾 / 序列分叉整笔放弃且不删新条目 / 索引有洞时接末位之后 / 目标是网络书时拒绝。
- `LocalBookImporterTest` 锁 `parseMetadata`：能拿到文件名里的书名作者、不写任何表、作者解不出时填显示用占位词。
- 变异自检：把 `findMatchesFor` 口径退回"只比归一化 `book_info.name`"→ 恰有同名不同作者、比对主键两条变红；把补章下一索引退回 `oldChapters.size` → 恰有索引有洞一条变红。两次变异均已还原，还原后测试全绿。
