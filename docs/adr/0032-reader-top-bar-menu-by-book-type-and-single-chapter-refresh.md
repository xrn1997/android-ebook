# 阅读器顶栏菜单按书籍类型分流，并新增单章刷新

阅读器顶栏「更多」菜单此前由**入口路径**开关（仅「从应用内打开且非本地书」时出现，菜单里只有下载与评论两项）。现改为按书籍**类型**直接决定菜单集合——本地书只留评论，网络书为下载 + 刷新 + 换源 + 评论——并新增「刷新当前章节」这一动作：已抓取的正文可能是坏的（站点回改正文、书源规则变更、旧规则解析出的内容有误），此前只能绕进下载面板做批量强制重下。

## 决策

1. **判据是书籍类型，不是入口路径**：顶栏取 `isLocalBook = bookShelf?.tag == LOCAL_TAG`。旧的 `showMore` 布尔量只在「从应用内打开且 tag 非本地」时置真——从别的应用分享/文件打开进来的网络书整场都看不到这个菜单。菜单该跟着书的属性走，而不是用户从哪扇门进来；书架实体在打开链路上就位（应用内路径直接来自 intent 数据，导入路径在归属检查时回填），不需要为菜单额外加载。
2. **菜单集合按类型裁剪**：本地书仅「评论」；网络书为「下载 + 刷新 + 换源 + 评论」。本地书的正文在用户导入的章文件里（`tag = loc_book`），下载/刷新/换源对它分别无意义或必败——没有可换的书源（仓库层以参数错误拒绝）、章文件就是最终源（`refreshChapter` 对本地书直接返回）、「重下」自己导入的文件更是骗人。「评论」两类都成立，故「更多」按钮常显（旧实现在无入口时用 48dp 占位块顶替）。
3. **「刷新当前章节」是读路径失效，不是下载**：`BookRepository.refreshChapter` 只做两件事——删该章章文件（`bookStore.deleteChapter`）、失效内存内容缓存（`contentCache.invalidateBook`），不自己发网络请求；重新抓取由页面重加载自然发生。内存缓存按**书**整体失效：它的粒度本就是书，只删文件不清内存会留下「同一本书其它页仍吃旧正文」的尾巴。
4. **刷新保留阅读位置**：`BookReadViewModel.refreshCurrentChapter` 返回当前 `(章号, 页码)`，页面经 `pagerController.setInitData` 就地重走加载链。刷新一章的目的不是从头再读一遍，落回首页等于把「修一章」变成「重读一遍」；内容变化导致页码越界时由既有的分页哨兵与钳位逻辑收口。
5. **与下载面板的批量强制刷新不合并**：下载面板的强制刷新标记服务于批量重下（多选、门槛是拉起前台服务、落在后台任务与常驻通知里），单章刷新是即时、同步返回的读路径失效。合并的代价是要么为刷新一章拉起前台服务与通知，要么把读路径失效硬塞进下载任务模型——两者都比多一条菜单项重。故下载面板里仍不单列「强制刷新缓存」（勾中已缓存章节即重下），本项只补「当前这一章」这个粒度。
6. **本地书不给灰置入口**：灰按钮仍占菜单宽度并要求用户理解「为什么不能点」，直接不给更清楚。

## 权衡

- **不做成顶栏一级图标按钮（与返回/更多并列）**：单章刷新是低频补救动作，不是高频阅读操作；摆在一级位置会让误触直接删掉当前章缓存（代价是一次重抓，且内容变化时阅读位置可能漂移）。
- **不用「换源」代替「刷新」**：换源是把这本书的归属从一条源搬到另一条源，改变此后所有章节的正文来源；当前章内容有误属于同一条源的缓存问题，用换源去修等于为了让一章变好而重绑整本书。
- **不为刷新引入新的失败态**：刷新自身不触网，删缓存后重抓若失败，走的是既有的正文加载失败呈现与重试入口，不新增一套「刷新失败了」的提示。

## 下游影响

- `lib_book_common`：`BookRepository` 新增 `refreshChapter(bookShelf, index)`（本地书提前返回；内容定位符按书自带 `tag` 构造）。该方法无测试引用。
- `module_book`：`ReaderTopBar` 形参 `showMore: Boolean` 改为 `isLocalBook: Boolean` 并新增 `onRefresh`；`ReadBookActivity` 删掉 `showMore` 状态与 `openBookFromApp` 的 `onShowMore` 回调，`onRefresh` 先收菜单再原地重载；`BookReadViewModel` 新增 `refreshCurrentChapter`；新增字符串 `R.string.refresh`。
- 显示条件由「打开路径」改成「书籍类型」后，从外部应用打开的网络书首次获得下载/刷新/换源入口（此前只有评论）。
- 刷新链路无自动化测试（`refreshChapter` 与 `refreshCurrentChapter` 均无测试引用）：删章文件、清内存缓存、原地重载三步落在真实 IO 与分页引擎上。可观测行为是网络书刷新后当前章重载且停留原位置，本地书菜单只剩评论。
