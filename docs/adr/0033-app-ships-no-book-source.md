# 应用零内置书源：书源清单只由用户导入，默认源改为每次现算

2026-09-11 定案。应用**不随包携带任何书源**：书源是指向第三方内容站点的访问配置（站点地址 + 抓取规则），随包分发等于由应用内置一份指向特定站点的访问配置、代用户建立访问关系；用户自备（自行导入社区 JSON 或本机文件）不受此限。据此删除 assets 里的内置书源清单、首启灌库、`is_user_imported` 列与整套「内置源不可删」保护，默认源改用每次从 Room 现算、不再有同步快照——内置源机制的一切派生件，其存在前提都是「应用自带一份书源」。

## 动机

- **合法性口径**：本应用不自带内容源。内置一份书源清单，等于随安装包下发一份「去哪儿抓、按什么规则抓」的配置，与「用户自备」在责任归属上不是一回事。删除它是为了消除这个口径冲突，不是为了削弱功能——用户导入、解析、管理书源的完整能力一条不动。

- **现状与口径冲突**：此前 `lib_book_common/src/main/assets/default_sources.json` 内置了一条「笔趣阁」源，首启由 `BookSourceManagerImpl.ensureSeeded()` 在 `book_source` 表为空时整批灌入 Room，行上标 `is_user_imported = false`；管理页据此把这类行的删除项置灰，DAO 的删除语句也带着 `AND is_user_imported = 1` 的保护条件。为了让书城首帧就有源名可写，还另有一套同步面：接口上的同步属性 `currentSource`、构造期读 assets 得到的冷启动清单，以及一份「默认源定义 + 其 parser」的内存快照。

- **拆一半的代价比全拆高**：只要 `is_user_imported` 列还在，就永远存在「哪一种行不可删」这个分支，以及「谁把行标成那种」这个提问；只要同步面还在，就还得在每个可能改到默认源那一行的写路径之后同步快照。留成死代码等于把一个已经破产的模型长期挂在接口上，后来者只能靠考古判断它为何存在。故本轮**整体拆除**，不留半套。

## 决策

1. **APK 内不含任何书源配置，`book_source` 表是书源清单的唯一事实源**。表里每一行都由用户导入而来，因此不再有「内置行受保护」这类特殊行，也没有任何 assets 回填路径。连带删除：assets 的 `default_sources.json`、`ensureSeeded()` 与它的可等待句柄（全部挂起入口与两个冷流的 `await()` 起手式一并消失，没有后台写任务要等）、内存快照 `defaultSnapshot` 与内部类 `DefaultSource`、`BookSourceItem.isUserImported`、`BookSourceEntity.isUserImported`。理由是这些件没有一件能独立存活：保护的对象不存在了，快照要覆盖的写路径也不再需要各自收敛。

2. **DAO 与删除路径去掉保护条件**：`deleteUserImported(url)` 改名 `deleteByUrl(url)`，语句里的 `AND is_user_imported = 1` 删除；返回 0 的唯一成因变成「这行本就不存在」；零调用方的 `getCount()`（首启灌库的判据）一并删除，不留零调用方 DAO 技术债。管理页去掉「内置」标记位与置灰的删除项，任何一条源都可删。**禁用不切断归属**这条既有语义不变：删掉源才会让绑它的书显示「书源已失效」。

3. **默认源每次从 Room 现算，SP 只记「用户上次主动选了哪个」**。候选是**全部启用行、不筛格式**（脚本行同样有资格当默认源），选择规则为「SP 命中且启用 → 否则第一条启用行」，收在实现类唯一一处 `defaultFromRows(rows)`；`observeDefaultSource()` 是默认源对外的唯一出口。`currentSource` 同步属性删除、内存快照删除、`getParserFor` 的默认源快路径删除——默认源的 parser 此后与其它源同构，一样进 LRU、一样由写路径的 `evictParser` 失效，于是「覆盖当前默认源」只需一次缓存失效，不再需要「连定义带 parser 一起换」这套口令。`defaultUrlFlow` 降格为**本次会话的重推信号**（`setDefaultSource` 对一条已启用的源只写 SP、不写库，没有它订阅面看不到这次切换），它与 SP 的写入必须成对完成。理由：默认源的真值只有 Room 一处，任何内存镜像都要求在 seeding、导入覆盖、启用/禁用、删除每一处之后同步，漏一处就是「库里已改、解析仍用旧值」且全程零报错。

4. **首帧没有同步初值，页面因此新增一个「还没有结论」档**。`LibrarySourceState` 增加 `Unknown`：书城页面组合的那一刻订阅还没回来，该档**整片留空**——既不画引导语，也不画半截切换器；Room 答复后才落进「有源 / 一条源都没有 / 源在但解析不出来」。理由是首帧的 null 与「没有源」是两件事：拿 `NoSource` 兜底，会让有源用户的每次冷启动都先闪一帧「请先导入书源」的误导文案与导入按钮。承接首装：书城零源空态新增「去导入书源」按钮，跨模块跳到书源管理页；模块独立运行时该路由不存在，由模块内的占位页经路径替换承接（独立模式下 TheRouter 找不到路由只记日志、不报错不闪退，不补占位就是一颗点了没反应的按钮）。

5. **书城的归属源经导航参数传入，不从全局默认源读**。分类列表页（`ChoiceBookViewModel`）的 `sourceUrl` 取自导航参数，请求一律带着它走。理由是书城顶部切换器本身就是「当前源是谁」的输入，页面自己再去读一次全局值，等于让同一次浏览有两个来源、且换源后旧页仍按旧源发请求。

6. **数据库 v6 → v7，两条语句且顺序不可颠倒**：先 `DELETE FROM book_source WHERE is_user_imported = 0` 清掉内置行，再 `ALTER TABLE book_source DROP COLUMN is_user_imported`。先删列就再也分不出哪些行是内置的（条件查询会以 `no such column` 失败）；后删列则让覆盖安装的库比全新安装多一列。`DROP COLUMN` 由随包 SQLite 承接（随包引擎实测 3.50.1，高于该语法所需的 3.35），该列非主键、无索引，不触及限制。迁移声明为 `internal` 而非 `private`：同模块测试要用生产同款引擎直接驱动它的 `migrate(connection)`，语句顺序与效果因此有回归覆盖。

7. **真源规则与真站 HTML 快照不入 git**。测试资源目录下曾入库一条真源的规则 JSON 与真站响应（含目录页与章节正文）快照，与「不随仓分发指向特定站点的抓取配置」是同一件事的两面。这两个测试资源目录（真源语料夹具与本地源池）加入 `.gitignore` 并从 git 移出（本地文件保留），录制器与回放链路不变；回放测试本就以 `assumeTrue` 跳过「无夹具」情形，夹具改为本地录制产物后行为一致。

8. **边界**：本次动的是「随包分发」这一种来历，不是书源能力本身。导入（原生规则与脚本两种出身）、解析、启用/禁用、设默认、删除、聚合搜索、书源管理页全部保留。应用仍需要用户提供至少一条源才能浏览书城，这不是缺功能而是本决策的定义。

## 权衡

- **零内置 vs 保留一条只读的内置源**：保留等于口径冲突原样存在（清单仍在包里）。选零内置，代价是首装用户进书城看到的是引导态而不是内容——由「去导入书源」入口把这一步缩短到两次点击，且不再存在「删掉内置源后无网收不回」这种要靠保护去兜的状态。

- **不留 `is_user_imported` 死列**：留着的直接收益为零，代价是每次读实体都要判断「这一列现在还有意义吗」，且 schema 里永远留着一个只能靠文档解释的历史字段。选删列，代价见「已知结果」——迁移不可逆。

- **`Unknown` 档 vs 首帧沿用上次的源名**：沿用上次值需要额外持久化一份「上次渲染的源」并在它失效时纠正，等于给首帧再造一处事实源，还会在源已被删时先画一颗点不动的切换器。选整片留空：首帧短、不撒谎，Room 答复即落定。

- **删除保护整体下线 vs 保留为「不可删的特殊行」通道**：将来若真有需要保护的行（例如订阅式书源），正确的做法是新增一列表达那件事，而不是复活一个语义已被拆除的旧列——旧列的名字与判据都绑在「内置」这件事上，复用等于把两个不同的概念挤进一个字段。

## 下游影响

- **`lib_ebook_db`**：`AppDatabase` version 6 → 7；`DatabaseModule` 追加 `MIGRATION_6_7`；`BookSourceEntity` 删 `isUserImported`；`BookSourceDao` 的 `deleteUserImported` → `deleteByUrl`、删 `getCount`；提交 Room 生成的 `7.json` schema；新增用裸 `SQLiteConnection` 驱动迁移的 `BookSourceMigration6To7Test`（测试依赖引入 `androidx.sqlite:sqlite-bundled-jvm`，即随包驱动的 JVM 变体）。
- **`lib_book_common`**：删 assets `default_sources.json`；`BookSourceManager` 删同步属性 `currentSource` 并重写相关 KDoc（接口顶部现在明写「本接口不再有同步读面」）；`BookSourceManagerImpl` 删冷启动清单、seeding、默认源快照与默认源 parser 快路径；`BookSourceItem` 的存在理由改写为「承载管理面专属的出身位」；具名测试替身 `FakeBookSourceManager`（两份）与各处内联实现同步去掉被删成员。

- **`module_me`**：书源管理页去掉「内置」标记与置灰删除项；导入落库不再写 `isUserImported`。
- **仓库资产**：`lib_book_source/src/test/resources/scripted_corpus/` 与 `.../book_source` 移出 git。

## 已知结果（不是回归）

装过携带内置源版本的设备（只在开发分支发布过）升级后，原本绑定那条源的藏书按既有语义显示「书源已失效」——源已随迁移删除，用户重新导入该书源即恢复。正式用户从未见过这条源：发布基线上根本没有 `book_source` 表，它是在本分支才建出来的。

## 遗留

- **不提供内置源的合法替代**：不做书源市场、推荐榜单或任何形式的内置分发渠道；用户从信任的外部来源自备。
- **不做首启引导页**：只做书城零源空态上的入口按钮，不做专门的引导页或弹窗。
- **`is_user_imported` 的语义不可恢复**：迁移后无法再区分「曾经是内置行」；将来若真需要「受保护的行」这类概念，要新加一列而不是复用旧列语义。
