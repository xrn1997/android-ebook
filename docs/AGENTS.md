# 文档规范

本文件定义本仓每份文档的职责、写作规则与生命周期。它只回答「这条内容该放哪、什么时候更新、什么时候归档」，不重复业务规则。

**一条事实只有一个家**：当前事实源只写现在时；历史与变更过程只进 ADR、CHANGELOG 或 git；读数住测试与代码注释；过程工件留在本机。别处只链接，不复述。

## 1. 分层与职责

| 层 | 文档 | 只负责 | 不负责 | 事实源 |
| --- | --- | --- | --- | --- |
| 常驻规则 | `AGENTS.md` | 跨会话必须可见的硬约束、仓库地图、命令速查、门 | 架构细节、教程、历史 | 是（仅规则） |
| 项目入口 | `README.md` | 是什么、模块图、快速开始 | 规则、决策、历史 | 是（用户可见事实） |
| 领域词汇 | `CONTEXT.md` | 术语、语义、`_Avoid_`（新/改词条点明实现符号） | 实现步骤、决策理由 | 是（词汇） |
| 当前架构 | `docs/architecture.md` | 模块依赖、核心接缝、各域不变量、唯一主人清单 | 为什么（→ ADR）、操作步骤（→ development）、历史 | 是 |
| 开发手册 | `docs/development.md` | 构建、运行、测试、工具链、mock/独立模块、混淆、日志 | 架构理由、业务规则 | 是（操作） |
| 贡献指南 | `CONTRIBUTING.md` | 提交规范、钩子、发版流程、提交前验证 | 架构、构建细节 | 是（流程） |
| 决策记录 | `docs/adr/` | 一个决策的 why、被否方案、后果 | 当前架构复述、计划、验收清单 | 是（why） |
| 稳定规格 | `docs/specs/` | 外部契约、语法/行为规格等长期事实源 | 一次性设计方案、施工步骤 | 是 |
| 书源参考 | `docs/book-source-rules.md` | 书源格式、导入、FAQ（面向用户/规则作者） | 引擎实现、沙箱细节 | 是（用法） |
| 版本政策 | `docs/versioning-practice.md` | SemVer、三问判据、versionCode、tag | 发布历史、提交类型 | 是（政策） |
| 测试缺口 | `docs/test-coverage-todo.md` | 未覆盖项的工作台账 | 测试规范、已完成细节 | 否 |
| 发布历史 | `CHANGELOG.md` | 每个版本的变更 | 版本政策 | 是（发布记录） |
| 读数 | 各模块 `src/test/**` 与代码注释 | 可复核的测试读数与局部口径 | 散文论证、用户可见事实 | 是（读数） |
| 过程工件 | 本机 `.superpowers/` | 任务简报、报告、审查草稿、一次性脚本 | 入库、作为事实源 | 否 |
| 生成快照 | `.qoder/repowiki/` | 工具生成的知识快照 | 手工维护、架构判断依据 | 否 |

本仓不设独立界面规格文档：界面状态与层级住 `docs/architecture.md` 与代码。`docs/specs/` 只在契约没有代码主人时存在：代码里的 DTO 与 Room 实体不另写规格。

## 2. 放置判据

- 每次会话都必须看到、且不看会做错的事 → 根 `AGENTS.md`。
- 用户装、用、数据在哪 → `README.md`。
- 词义与它的唯一实现 → `CONTEXT.md`。
- 当前代码/运行时的结构、机制、不变量 → `docs/architecture.md`。
- 怎么构建、运行、测试、配置工具链 → `docs/development.md`。
- 怎么提交、钩子怎么装、版本怎么定 → `CONTRIBUTING.md`（版本判据细节在 `docs/versioning-practice.md`）。
- 为什么选这个方案、放弃了什么 → `docs/adr/`。
- 跨仓库契约、语法/行为规格 → `docs/specs/`。
- 书源格式与用法 → `docs/book-source-rules.md`。
- 测试缺口 → `docs/test-coverage-todo.md`；发布历史 → `CHANGELOG.md`。
- 进行中的计划、审查、调研 → 本机 `.superpowers/`；完成后把长期成立的部分提炼进 ADR、architecture 或 specs，其余不落库。
- 拿不准时按「读者在什么场景会打开它」选层。

本仓为单上下文仓库，无 `CONTEXT-MAP.md`；领域词义只查 `CONTEXT.md`。

## 3. 写作规则

1. 当前事实源只写现在时。历史、变更过程、旧方案只进 ADR、CHANGELOG 或 git；不在 architecture/development 里写「已改为」「曾经」「下一步计划」。
2. 当前事实源里一个事实只有一个家。同一结论在两份当前事实源里出现就是错误：保留更合适的那个，另一个改成链接。根 `AGENTS.md` 的 standing-order 摘要与 `docs/architecture.md` 的详细机制是「摘要 + 详情」关系，不算重复；摘要不得复述机制。
3. 代码与配置是最终事实源。文档写「为什么、不变量、入口、不能怎么做」，不逐行复述实现；具体类名/签名可能变化时用链接而非粘贴。
4. 链接用相对 Markdown，不要写裸路径；指向标题时用 GitHub 生成的 slug。移动文件必须同步更新入链。点名的仓内路径必须真实存在；Markdown 链接由 `bash scripts/check-docs.sh` 检查，反引号里的路径靠人工核对。
5. 不写行号（`file.ext:123` 形态会随任何一次编辑漂移）；要指实现就指符号锚。
6. 不抄会腐烂的读数与计数；需要证据就指测试、代码或 ADR 的 `锚点：`。
7. 注释与文档承担为什么、不变量、裁决、证据，不承担代码细节；自测问题：这句删掉，读者丢的是「为什么」还是「怎么做」？只丢后者就删或升高度。
8. 词汇优先：新概念先进 `CONTEXT.md` 并点明实现符号，再写代码；改口径时同批补符号。
9. ADR 的写作、状态与取代规则住 `docs/adr/ADR-FORMAT.md`；一篇 ADR 只回答一个决定。
10. `.qoder/repowiki/` 是生成快照，不手改、不作架构判断依据，也不把它的结论抄进手写文档；需要架构判断时以代码与 `docs/architecture.md` 为准。
11. 根 `AGENTS.md` 预算 ≤ 8,000 字符（`wc -m`，中文按字符数）；超限按「搬迁 → 压缩 → 提额并说明」处理，提额必须在提交信息里写理由。
12. 过程工件不进仓库：计划/审查/调研/脚本只住本机 `.superpowers/`；仓库不设过程归档目录。
13. 引用外部文档原文不得改写；自家表述可直接改，引用只能在其之外另加读法说明，否则等于伪造出处。

## 4. 生命周期

- **ADR**：编号只追加、不复用；每篇紧跟标题写 `Status: accepted` 或 `Status: superseded by NNNN`；每篇在 `docs/adr/README.md` 恰好出现一次；文末必须有 `锚点：`；正文只写当前真相，日期留在 git；整篇翻案新写一篇并标旧篇，事实漂移就地改。
- **当前事实源**（`README.md`、`CONTEXT.md`、`docs/architecture.md`、`docs/development.md`）：语义、结构或操作变化时同批更新；不写历史。
- **稳定规格**（`docs/specs/`）：只放长期成立、跨版本仍要遵守的契约/语法/行为规格；每份开头必须有 `状态：生效（YYYY-MM-DD）`；行为变更时同步改规格与实现，不允许「代码已改、规格仍是旧描述」。
- **书源参考与版本政策**：用户面格式/策略变化时同批更新；发布历史只进 `CHANGELOG.md`。
- **CONTRIBUTING**：提交规范、钩子、提交前验证或发版边界变化时同批更新；构建步骤仍住 `docs/development.md`。
- **CHANGELOG**：只在发版时追加已发布版本；写用户可见变化与升级注意，未发布改动不预写；逐提交明细留 git。
- **过程工件**：只住本机 `.superpowers/`；仓库不设 `docs/superpowers/`、plans/specs/archive；需要长期保留的结论提炼进 ADR、architecture 或 specs。
- **生成快照**：整棵树重新生成，不逐文件修；与代码冲突时以代码为准。
- **文档门**：提交前跑 `bash scripts/check-docs.sh`；它检查根 AGENTS 预算、相对链接、规格状态头、ADR 索引/状态/锚点、核心文件、已废引用与过程归档目录不存在。仓库无 CI，门不会替你跑。

## 5. 评审清单

文档改动提交前自查：

- 这条事实的家是否唯一？别处是否还有旧副本？
- 当前事实源里有没有混进历史/计划口吻？
- 改动的路径、相对链接/锚点、ADR 编号、`§N` 指路是否都还活着？（`bash scripts/check-docs.sh`）
- ADR 的 `Status`、索引、`锚点：` 是否齐全？
- 根 `AGENTS.md` 是否仍在预算内？新增规则是否附了指针？
- 过程工件是否留在本机、没有入库？
- 生成的 `.qoder/repowiki/` 是否没有被手改？
- `CONTEXT.md` 新增或改动的 `_唯一实现_` 符号是否现查得到？
