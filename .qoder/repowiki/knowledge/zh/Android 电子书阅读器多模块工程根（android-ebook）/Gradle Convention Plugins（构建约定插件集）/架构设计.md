采用 Gradle `kotlin-dsl` 插件聚合构建工程：根 `settings.gradle.kts` 声明子工程 `:convention`，并在 `pluginManagement` 与 `dependencyResolutionManagement` 中通过版本目录 `../gradle/libs.versions.toml` 统一管理依赖；`convention/build.gradle.kts` 用 `plugins { alias(libs.plugins.android.lint) }` 加载 lint 并声明所有第三方 Gradle 插件为 `compileOnly`，再通过 `gradlePlugin { plugins.register(...) }` 将每个 `*ConventionPlugin` 类以 `xrn1997.*` 前缀的自定义 ID（如 `xrn1997.android.application`、`xrn1997.hilt`、`xrn1997.android.room`）注册到产物 `META-INF/gradle-plugins/`，供根项目与应用各模块按相同插件 ID 引用。

内部层次划分清晰：
- `com.xrn1997.convention.*` 包下的 Kotlin/Gson/Lint/Hilt/Compose 等扩展函数是纯配置辅助（如 `configureKotlinAndroid`、`configureGradleManagedDevices`、`configurePrintApksTask`），被各 Plugin 复用。
- 顶层的 `AndroidApplicationConventionPlugin`、`AndroidLibraryConventionPlugin`、`AndroidComponentConventionPlugin`、`AndroidComposeConventionPlugin`、`AndroidRoomConventionPlugin`、`AndroidLintConventionPlugin`、`HiltConventionPlugin` 各自 `apply(plugin = ...) + extensions.configure<...>` 组合 AGP 能力，并通过 `withPlugin("org.jetbrains.kotlin.jvm" | "com.android.base")` 进行条件装配。
- 独立子工程约束在 `build-logic` 自身启用并行、缓存、按需配置（`gradle.properties`）。
依赖方向单一：Convention 插件只读取版本目录（通过 `Project.libs` 扩展）与被包含的基础插件，不被业务模块反向引用。
