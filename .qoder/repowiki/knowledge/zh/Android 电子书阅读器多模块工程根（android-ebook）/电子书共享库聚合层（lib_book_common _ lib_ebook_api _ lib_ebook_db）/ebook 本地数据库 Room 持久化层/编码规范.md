- DAO 方法对可观察数据成对提供 suspend 快照与 Flow 变体（如 `getAllBooks` / `getAllBooksFlow`、`count` / `observeRemainingCount`），让 UI 按需选择一次性读取或响应式监听
- 实体主键一律采用自然键（`note_url`、`content_ref`），仅流水型表（download_chapter、search_history）使用自增 `id`；新增字段改名需走迁移链而非删表重建
- 写操作统一使用 `@Insert(onConflict = OnConflictStrategy.REPLACE)` 实现 upsert，避免先查后写的竞争；更新进度等半量写入场景改为整行 REPLACE 以避免未赋值字段被默认值覆盖
- 实体间不声明外键与级联删除，跨表清理责任全部上移到调用方（DAO 注释反复强调「由 BookRepository.removeFromShelf 等上层仓库负责」），保持 DAO 仅关注单表语义
- `@Relation` 查询（如 `BookShelfFullInfo`）统一包裹在 `@Transaction` 中，防止关联子查询在主查询之后因并发写产生「书已删、章节仍在」的中间态
- Room migration 脚本以 `object : Migration(n, n+1)` 形式定义并使用 `SQLiteConnection.execSQL` 手写 DDL，迁移文档直接内嵌于 `DatabaseModule` 常量注释中说明变更原因
