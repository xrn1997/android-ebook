模块按 `com.ebook.api` 下子包分层组织：
- `config/API.kt` 集中管理 ebook-server 基址（主机从 `BuildConfig.EBOOK_SERVER_HOST` 注入，端口固定 9090），是各服务 URL 的唯一来源。
- `entity/` 存放 kotlinx-serialization 注解的数据类，所有请求 DTO 以 `@SerialName` 对齐服务端蛇形字段；业务实体遵循「客户端内部命名不变，仅在序列化边界映射」策略。
- `service/{user,comment,release,source}/` 通过 `NetworkDataSource` 接口 + `*Network` 实现分离契约与真实后端实现；每个 Network 用 `RetrofitBuilder` 创建独立 Retrofit 实例绑定对应 host:port，仅透传 Retrofit Service 层的 suspend 方法，不写业务分支。
- `utils/RetrofitBuilder.kt` 复用 lib_common 共享 `Call.Factory`（含 AuthInterceptor、debug 脱敏日志），并显式挂入 kotlinx Json 转换器与 Scalars 转换器（适配纯 String HTML 返回）。
- `utils/CoroutineAdapter.kt` 是所有仓库层调用的统一入口：在 IO 线程执行、把 `RespDTO.code` 转 `Result`、拦截 `A0230` 触发 `TokenRefresher` 静默刷新一次并重放失败则发 `SessionEvent.SessionExpired`，由上层统一清会话跳转。
- `auth/` 定义 `TokenRefresher` 接口与其 `SessionEventBus`，具体刷新实现放在上层 `lib_book_common`，通过 Hilt @Binds 注入以避免反向依赖。
- `intercepter/EncodingInterceptor` 负责 UTF-8 编码兜底（面向中文 URL）。
- `cache/ACache` 提供轻量本地缓存能力。
- Hilt 依赖注入集中在 `utils/NetworkModule`：以 `@Named("source")` / `@Named("release")` 区分纯净 OkHttpClient（不带 token、无认证链路，分别用于第三方书源抓取与 GitHub/Gitcode Releases 检查）。
