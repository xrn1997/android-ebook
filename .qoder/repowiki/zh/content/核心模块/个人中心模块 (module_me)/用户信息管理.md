## 简介
本文件围绕“用户信息管理”功能展开，重点说明个人资料编辑界面的实现与数据流。内容涵盖：
- 修改头像、昵称的界面入口与交互流程；
- ModifyInformationActivity 的页面架构与状态驱动方式；
- ModifyNicknameActivity 的输入校验与提交逻辑；
- 头像裁剪功能的完整链路（图片选择、圆形裁剪区、结果返回）；
- ModifyViewModel 的状态管理与异步更新；
- ModifyRepository 与后端 API 的交互；
- 完整的用户信息更新数据流与错误处理机制。

该功能采用 MVVM + Compose 架构，通过单一 ViewModel 暴露 profileState，让多个页面共享并刷新当前昵称和头像。网络请求由 Repository 层封装，失败统一上报，避免在 Activity 中散落业务细节。

## 项目结构
用户信息管理相关代码集中在 module_me 模块中，按职责分为视图层、视图模型层和数据仓库层：
- 视图层：负责 UI 展示和用户交互；
- 视图模型层：聚合 ProfileRepository 的数据流，处理本地状态与提交闸门；
- 仓库层：封装后端接口调用、图片字节读取与上传。

## 核心组件
- ModifyInformationActivity：资料编辑主界面，提供头像、昵称、密码三个条目；头像通过底部弹窗选择拍照或相册，随后进入裁剪页。
- ModifyNicknameActivity：昵称编辑页，包含当前昵称参照、新昵称输入框、长度计数与确认按钮。
- ClipImageActivity：头像裁剪页，支持单指拖动、双指缩放，固定圆形裁剪区域，确认后返回裁剪后的图片 Uri。
- ModifyViewModel：集中管理 profileState，提供 modifyNickname 与 modifyProfilePhoto 两个可观察的更新入口，并通过 submitInProgress 防止重复提交。
- ModifyRepository：封装昵称更新与头像上传两步流程，统一使用 safeApiCall 与 mapCatching 处理成功/失败分支。

## 详细组件分析

### 个人资料编辑界面：ModifyInformationActivity
- 页面以 Compose 列表形式展示当前昵称与头像缩略图，点击行进入对应编辑。
- 头像更换流程：
  - 点击“修改头像”弹出 ModalBottomSheet，提供“拍照”“从相册选择”两个选项；
  - 拍照生成临时文件并构造 ContentUri，相册选择直接返回 Uri；
  - 将 Uri 传递给 ClipImageActivity 进行圆形裁剪；
  - 裁剪成功后回调到 Activity，再调用 ViewModel.modifyProfilePhoto(uri) 完成上传。
- 密码修改入口根据是否集成登录模块动态显示，避免独立运行时误跳模拟登录页。

关键要点：
- 页面不直接访问 ProfileRepository，而是消费 ViewModel.profileState；
- 多次拍照复用同一临时文件，避免缓存堆积；
- 选图使用 PickVisualMedia，Android 13+ 免权限；
- 裁剪结果通过 ActivityResultContracts.StartActivityForResult 返回。

### 昵称编辑界面：ModifyNicknameActivity
- 页面包含“当前昵称”参考文本、新昵称输入框、输入计数与确认按钮。
- 输入校验规则：
  - 非纯空白；
  - 最大长度为 12；
  - 输入为空时显示错误提示，输入计数实时反馈；
  - ImeAction.Done 与按钮点击均会触发提交。
- 提交逻辑：
  - 调用 ViewModel.modifyNickname(trimmed)；
  - ViewModel 内部进行 Loading 与提交闸门控制；
  - 成功后刷新本地昵称并关闭页面。

注意：
- nickname 使用 rememberSaveable 保留旋转或重建时的输入；
- 当前昵称为空时显示“未设置”，用于首启或仅邮箱注册的用户。

### 头像裁剪功能：ClipImageActivity
- 加载图片：
  - 从 Intent.data 获取 Uri；
  - 在 IO 线程采样解码（720×1280），并进行 EXIF 旋转纠正；
  - 加载失败显示错误文案，加载中显示进度指示。
- 手势交互：
  - 单指拖动平移图片；
  - 双指缩放，缩放范围限制为 minScale 到 4*minScale；
  - 圆形裁剪区固定在容器中央，约束偏移确保圆内不露白。
- 结果返回：
  - 确认按钮启用条件为 cropState 已就绪；
  - 裁剪产物为 200px 正方形位图，压缩为 JPEG 写入缓存目录；
  - 通过 setResult 返回 ContentUri，上层可继续上传。

关键点：
- 使用 CompositingStrategy.Offscreen + BlendMode.Clear 实现遮罩挖孔；
- 裁剪输出大小与预览采样一致，避免上传后出现锯齿差异；
- 连点确认有闸门保护，避免重复写盘与重复返回结果。

### 视图模型：ModifyViewModel
- 状态管理：
  - profileState 通过 combine(ProfileRepository.nickname, ProfileRepository.pictureUrl) 生成；
  - 使用 stateIn 将组合流转为 StateFlow，订阅期间维护值，无订阅时延迟启动。
- 提交闸门：
  - submitInProgress 防止昵称与头像同时提交；
  - 每次提交前设置为 true，finally 中复位。
- 修改昵称：
  - 设置 Overlay.Loading；
  - 调用 Repository.modifyNickname；
  - 成功：Toast 提示、更新本地昵称、finish；
  - 失败：reportFailure 上报异常。
- 修改头像：
  - 设置 Overlay.Loading；
  - 调用 Repository.modifyProfilePhoto；
  - 成功：Toast 提示，若 URL 非空则更新本地头像；
  - 失败：以“上传头像失败：{userMessage}”格式提示。

### 数据仓库：ModifyRepository
- 修改昵称：
  - 使用 UpdateUserRequest(nickname = name) 调用部分更新接口；
  - 服务端废弃旧端点，统一走本端点；
  - 成功返回 Unit，失败抛出异常并携带资源文案。
- 修改头像（两步流程）：
  - 第一步：IO 线程读取 Uri 对应文件的字节，构建 MultipartBody.Part 上传到 /api/uploads/avatar；
  - 第二步：将返回的 avatar URL 再次调用 updateMe(UpdateUserRequest(avatar = url)) 更新资料；
  - 任一步失败都会抛出异常，并由上层 reportFailure 处理。

注意：
- 图片读取与上传必须切 IO 线程，避免阻塞主线程；
- 文件名通过 FileUtil.generateFileName("jpg") 生成，保证唯一性；
- 响应体 data 为空时抛出异常，避免空指针导致 UI 状态不一致。

## 性能与资源管理
- 图片采样解码：ClipImageActivity 使用 720×1280 采样解码，避免大图的 OOM；
- IO 线程隔离：头像字节读取、JPEG 压缩与文件写入均在 Dispatchers.IO 执行；
- 内存回收：裁剪完成后对 Bitmap 调用 recycle，避免泄漏；
- 临时文件：拍照与裁剪结果使用缓存目录中的临时文件，减少磁盘占用；
- 状态订阅优化：profileState 使用 WhileSubscribed(5_000)，在无订阅时停止合并流，降低后台开销；
- 防重复提交：submitInProgress 闸门避免慢网下重复 PUT 与重复提示。

## 故障排查指南
- 昵称修改失败：
  - 检查输入是否为纯空白或超过 12 字；
  - 查看 ViewModel 中 reportFailure 上报的异常信息；
  - 确认 Repository.modifyNickname 返回的 data 是否为空。
- 头像上传失败：
  - 检查 Uri 是否能成功读取字节；
  - 查看 uploadAvatar 与 updateMe 的返回码与响应体；
  - 注意“上传头像失败：{userMessage}”的提示，结合 userMessage 定位问题。
- 裁剪页面无法操作：
  - 确认 cropState 是否已就绪（需等待 onSizeChanged）；
  - 检查手势是否被遮挡或容器尺寸异常；
  - 确认图片加载是否成功，失败时显示错误文案。
- 会话过期与全局错误：
  - 会话过期已在网络层全局处置，ViewModel 不再重复提示；
  - 其他异常通过 reportFailure 统一上报，便于日志追踪。

## 结论
用户信息管理功能通过清晰的 MVVM 分层与 Compose 化界面，实现了昵称修改、头像上传与裁剪的完整闭环。ModifyInformationActivity 负责入口与交互编排，ModifyNicknameActivity 负责表单校验，ClipImageActivity 负责图片裁剪，ModifyViewModel 统一状态与提交流程，ModifyRepository 统一网络调用。整体设计强调：
- 单一数据源（profileState）驱动 UI；
- 提交闸门避免重复请求；
- IO 与主线程分离，保障流畅体验；
